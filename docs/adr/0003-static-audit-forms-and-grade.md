# ADR 0003 — تدقيق الكود الثابت، فحص النماذج، ودرجة الجودة

التاريخ: ٢٠٢٦-٠٦-٠٨
الحالة: مقبول ومطبّق

## السياق
لاكتمال «المختبِر البشري» يلزم تغطية ما لا يراه المتصفح (الباك إند/قاعدة
البيانات/الأسرار على مستوى المصدر)، وسلوك المختبِر مع النماذج، وحُكم نهائي
يقرأه صاحب القرار بنظرة واحدة.

## القرار
- `audit.static` + محرّك `staticAudit`: مسح مصدر المشروع (يشمل مجلدات الباك إند
  وقاعدة البيانات) لرصد الأسرار المكتوبة، حقن SQL، المال كـ float (قانون هاسان)،
  eval، حقن الأوامر، XSS عبر innerHTML، وملف .env مكشوف — بـ file:line. لا يقرأ
  محتوى .env احتراماً لقاعدة الأسرار.
- `forms.validation` + محرّك `formAudit`: فحص تحقّق النماذج **بأمان بلا إرسال**
  (لا يُنشئ بيانات) — نموذج بلا تحقّق، بريد غير مكتوب كـ email، كلمة مرور بلا حدّ.
- `gradeReport`: درجة جودة كلية (A+…F) وحُكم تنفيذي، تُعرض كشارة أعلى التقرير.
- توسعة أنماط الاكتشاف الافتراضية لتشمل ملفات الجذر ومجلدات backend/db/services/
  models/migrations — كي يغطّي التدقيق الباك إند وقاعدة البيانات فعلياً.

## البدائل المرفوضة
- إرسال النماذج فعلياً لاختبارها: يخاطر بإنشاء/تغيير بيانات؛ فحص القيود في
  المتصفح آمن وكافٍ لرصد غياب التحقّق.
- ربط قاعدة البيانات مباشرة: يحتاج بيانات اعتماد وامتيازات خارج النطاق الآمن؛
  التدقيق الثابت للمصدر + آثار الـAPI يغطّيان المخاطر الأهم.

## النتائج
- ٢٣ سيناريو مدمجاً، ٨ طبقات ملاحظات، ودرجة جودة كلية.
- مُتحقَّق حياً: التدقيق الثابت رصد السرّ وحقن SQL والمال-float وeval بـ file:line؛
  التطبيق التجريبي المعطوب قصداً حصل على F (٢٦/١٠٠).
- اختبارات وحدة: gradeReport و staticAudit (المجموع ٤٣ اختباراً، كلها خضراء).
