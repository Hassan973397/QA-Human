# ADR 0006 — إعادة استخدام سياق المتصفح لكل دور (دخول مرة واحدة)

التاريخ: ٢٠٢٦-٠٦-٠٨
الحالة: مقبول ومطبّق

## السياق
شكوى المستخدم: الأداة «تسجّل الدخول ١٠ مرات وتفتح نوافذ متصفح كثيرة». السبب:
المحرّك كان يُنشئ **سياقاً معزولاً جديداً لكل دور في كل سيناريو** ثم يُغلقه —
فمع ٢٦ سيناريو تنفتح/تُغلق عشرات النوافذ، وكان `prepareHumans` يفحص
`hasStorageState` (يبقى false داخل التشغيل) فيُعيد تسجيل الدخول كل سيناريو.

## القرار
- **تجميع السياقات**: سياق واحد لكل دور يُعاد استخدامه عبر كل السيناريوهات
  (`browser.reuseContexts`، افتراضي true). نافذة واحدة لكل دور، وتسجيل دخول مرة
  واحدة للتشغيل كله.
- **علم `authenticated`** على سياق الدور: يصير true بعد أول دخول ناجح، ويُعاد عبر
  `RoleContext.hasStorageState` كي لا يُعيد الرنر تسجيل الدخول.
- **مراقبات عبر `ReporterRef` متغيّر**: الصفحة المُعاد استخدامها تكتب أخطاء
  الكونسول/الشبكة لتقرير السيناريو **الحالي**.
- **التتبّع عبر chunks** لكل سيناريو (تبقى روابط التتبّع في التقرير)، والفيديو
  يُحفظ لكل دور عند الإغلاق النهائي حسب السياسة.
- **مسار احتياطي**: `--fresh-contexts` (أو `reuseContexts:false`) يرجّع السلوك
  الكلاسيكي (سياق/فيديو مستقل لكل سيناريو، نوافذ أكثر).

## النتائج
- مُتحقَّق حياً: عبر ٢٦ سيناريو، **تسجيل الدخول مرة واحدة فقط** (كان مرة لكل
  سيناريو)، و١٩ ناجح بلا فشل. الوضع الكلاسيكي ما زال يعمل.
